PROBLEM FOUND
The ERP stores its shared data in one Supabase row. In v499, if another laptop saved after this page loaded, the first laptop either stayed in a repeated conflict or replaced unrelated newer cloud work with its complete older copy.

FIX IN v500
1. Every local save records only the changed top-level record, field, addition, or deletion in a persistent pending-change journal.
2. Before upload, v500 reads the newest Supabase row and applies those pending changes to that newest copy.
3. If both laptops changed different fields of one record, both changes are retained.
4. If another save happens during upload, v500 reads, merges, and retries up to three times.
5. The journal remains on the laptop until Supabase confirms the cloud save.
6. Factory Out Bill rows are rebuilt from the merged Bill data before upload.
7. Pending work retries on internet recovery, window focus, page visibility, and every 15-second background cycle.

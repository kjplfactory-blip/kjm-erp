KHUSHALI JEWELLS MANUFACTURING ERP v499 - DATA RECOVERY

AUTOMATIC PROTECTION
- Before a new app version writes to the main cloud row, it creates a version-upgrade backup.
- Before the first cloud save each day, it creates a daily backup.
- Automatic backups are stored in public.erp_state_backups.
- Website users can read and insert backups but cannot edit or delete them.
- Optional cloud backups protect older versions; normal saving still uses a conditional live-row check when the backup table is unavailable.
- Automatic app refresh preserves the Create Job Order draft and the local ERP safety copy before opening a new version.

ONE-TIME SETUP
1. Open Supabase Dashboard > SQL Editor.
2. Run ENABLE-CLOUD-SAFETY-BACKUPS.sql from this folder.
3. Run ENABLE-APP-VERSION-GUARD.sql once.
4. Open the ERP and confirm the top status returns to Live Sync.

WHEN DATA LOOKS WRONG
1. Do not reset data and do not upload the wrong laptop copy.
2. If any laptop still shows the complete data, do not refresh it.
3. Log in as Owner and press Backup Data immediately.
4. Preserve that downloaded JSON file before doing anything else.
5. Run READ-ONLY-CLOUD-DATA-CHECK.sql in Supabase SQL Editor.
6. If backup_table_exists is false, the error only means backup setup was never completed; it does not mean erp_state was deleted.
7. If backup_table_exists is true, run READ-CLOUD-BACKUPS-AFTER-SETUP.sql.
8. Compare the live counts with the backup profiles and identify the latest complete backup.
9. Do not restore a backup until its orders, lots, designs, bills, and safe-item counts have been checked.

MANUAL DOWNLOAD BACKUP
- Owner > Backup Data downloads a complete JSON recovery file.
- Keep periodic copies in OneDrive or another protected drive.
- Restore Backup first restores locally so records can be checked before Owner uploads them live.

IMPORTANT
Application ZIP files contain the software only. They do not contain live ERP records.
